Git worktrees for parallel AI coding agents: setup and gotchas

Running two coding agents in the same folder works until the first time one rewrites a file the other is halfway through, or one agent's npm install breaks the other's build. The fix is old and boring: give each agent its own git worktree.

Why a worktree, not a clone or a branch

  • A branch switch changes the one working folder everyone shares. It can't isolate two agents.
  • A full clone isolates, but duplicates history, and agents' commits don't see each other until pushed and fetched.
  • A worktree gives each agent its own files, index and branch, while sharing one object database. Commits are visible everywhere immediately, and merging is ordinary git.

Setup in three commands

git worktree add -b agent/search-filters ../app-agent-1 main
git worktree add -b agent/fix-timezone  ../app-agent-2 main
git worktree list

Start each agent with its working directory set to its own folder. Some tools now do this for you: Claude Code, for example, can create worktrees under .claude/worktrees/ inside the repo (add that path to .gitignore). Whatever creates them, they're ordinary git worktrees and every command here applies.

Gotcha 1: ignored files don't exist in the new worktree

Git checks out tracked files only. A fresh worktree has no node_modules, no .env, no local config, no keystore, no generated plists. The agent's first build fails, or worse, succeeds with missing config and produces something subtly wrong. Fix it once with a setup script and run it on every new worktree:

#!/bin/sh
# usage: setup-worktree.sh <main-checkout> (run inside the new worktree)
main="$1"
for f in .env .env.local; do
  [ -f "$main/$f" ] && cp "$main/$f" .
done
npm ci

Copy secrets rather than symlinking them if an agent might edit them. Always check the build output for what you assumed was included.

Gotcha 2: two dev servers, one port

Both agents start npm run dev and the second dies on EADDRINUSE, or worse, a browser tab shows the wrong worktree's app. Give each worktree an explicit port (PORT=3001, 3002) in its local env file. The same applies to databases, emulators and anything else bound to a fixed local port.

Gotcha 3: the one-branch lock

Git won't let two worktrees hold the same branch. This protects you, and it's why each agent needs its own branch name. If an agent is told to "check out main" while main is checked out in your home folder, it'll fail. Have agents work on their own branches and merge into main from your home checkout.

Gotcha 4: cleanup debt

Agents leave worktrees behind. A week in you have a dozen folders, half with uncommitted changes nobody remembers. Build a habit: when a branch merges, git worktree remove its folder and delete the branch. git worktree list shows what's outstanding, and git worktree prune clears records for folders deleted by hand.

Gotcha 5: merging N branches back

Parallel agents touching the same files means conflicts later. Give each agent a clearly separate area, merge the smallest changes first, and rebase the rest onto the result before merging. Review each diff as a normal pull request. The worktree isolates the work, but it doesn't make it correct.

FAQ

Why does each AI coding agent need its own worktree?

Agents edit files and run builds. In one folder they overwrite each other's edits and break each other's builds. Separate worktrees isolate files, index and branch while sharing history.

Why is my new worktree missing node_modules and .env?

Git only checks out tracked files. Ignored files exist only where they were created, so each worktree needs its own install and a copy of local config.

Can two worktrees run the same dev server?

Not on the same port. Give each worktree its own PORT.
